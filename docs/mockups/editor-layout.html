What this is

A layout mockup for the map editor — not a working editor. Nothing here is wired to the engine, the viewports are drawn SVG, and the perspective view is a placeholder where the WebGPU canvas goes. Its job is to settle two things before any editor code is written: what the panels are called, and what happens to each one when the screen is a phone.

Breakpoints

  • Desktop, ≥ 1100px — the Worldcraft shape. Four views, three docks, everything visible at once. Above 1700px the docks widen rather than the whitespace.
  • Tablet, 720–1099px — one view with a view picker, rail and inspector stay, the outliner and palette become a drawer over the viewport. Touch cluster appears at the thumb.
  • Phone, < 720px — the view is the whole screen. Toolbar, rail and docks are gone; the toolbelt opens one panel at a time as a sheet.

These are container queries, not media queries — the layout answers to the frame it is mounted in. That is why the buttons at the top of this page show the real phone and tablet layouts on a desktop monitor, and it is the same mechanism that would let a dock in the real editor lay itself out correctly at any width it is dragged to.

What the phone deliberately does not do

The phone target is view, navigate, tweak params, place and move brushes — not full authoring. Being explicit about the line is the point:

  • Per-vertex manipulation is desktop-only. Dragging a single vertex with a finger, on a map where vertices are 8 units apart, is an unsolved interaction. The phone gets numeric fields in the Inspector instead, which are precise and boring and work.
  • The material graph is read-and-tweak on a phone. Pan, zoom, select a node, change its numbers. Wiring nodes — dragging between two 6px ports — is desktop and tablet.
  • The script board is the same: read, inspect, change constants. Rewiring is desktop.
  • Multi-view is desktop-only. Four ortho views on a 390px screen is four useless views; the phone gets one, switched.

Things worth arguing about

  • The graph is a takeover, not a dock. A node graph in a 300px dock is unusable at any screen size, so it takes the deck and hands it back.
  • The Inspector is one panel with three tabs (Brush / Surface / Entity) rather than three docks, because the selection decides which one you want and the tab can follow it.
  • Build is a panel, not a button. It is slow, it fails, and it needs somewhere to say so.
  • Every panel is mounted, not duplicated — one DOM node moves between dock, drawer, and sheet as the layout changes. Whatever the real editor is built from, that property is the one to keep.
